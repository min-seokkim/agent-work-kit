# Changelog

Behavior changes per version. Items to check when moving from an earlier version are listed under "Incompatible changes". The version is not raised per commit; changes until the next release are added to the unreleased section at the top.

## 0.3.0 (unreleased)

Planned as the first public release. 0.2.0 existed only as the version in the source and was never tagged or released. From 0.3.0 the package goes to PyPI and GitHub releases, once the release conditions in [docs/release.md](docs/release.md#release) are met. Changes until then are added here.

### Commands

- `kit guide windows-recovery` prints the complete Windows review path-recovery topic, included in packages and copied kits. The reference keeps its original recovery heading and fragment, with a whole-file link to the topic.

- `review check` retains an additive `failure` object with the phase and original error for caught runner exceptions saved as `uncertain`, including failures before checks start and after steps finish. The CLI reports the run location and preserves the original error if saving its diagnostic fails. Existing status/exit meanings, step history, cleanup and incomplete shared publication remain. The reference documents custom-root lookup/hook configuration and tested repository-local Windows path recovery.

- `review preview --config PATH [--json]` observes the current folder's artifact selection before checks. Schema-1 JSON retains paths, stat sizes, optional/required pattern associations, unmatched patterns and coverage errors; text shows counts and the 20 largest files. It reads no artifact contents and creates no snapshot, run or store. Linked branches or unavailable metadata produce partial observations; current missing matches do not predict future check failure. Existing collectors retain their mode-specific rules.

- Preview follows Python 3.12's literal-segment enumeration, preserving actual filename spelling, Windows Unicode matches and selection deduplication. Other Python versions and artifact collectors retain their existing behavior.

- Check configuration accepts `artifact_storage = "shared"` for new runs; absent or `"copy"` preserves ordinary copies. Collection-local SHA-256 objects share identical configured bytes, with a versioned descriptor, schema-2 manifests and explicit publication state. Existing verify, accept and compare commands read shared evidence; acceptance creates independent ordinary files. Corrupt references produce failing comparison integrity results without unverified diffs. Direct artifact diagnostics remain local, declared evidence; collisions preserve bytes and record failed, incomplete publication.

- `review export RUN --output DEST` creates an independent schema-1 bundle at a nonexistent destination, preserving original metadata and artifact associations under export provenance. It includes direct diagnostics and excludes retained worktrees. Storage inspection uses schema-2 JSON to separate run-local bytes, shared objects counted once, per-run references and unreferenced objects with coverage limits. Existing copied history is unchanged; switching future checks to copy leaves earlier shared runs dependent on their store or an independent export.

- `review storage [--runs-root DIR] [--json]` inspects existing review stores without writes or initialization. Schema-1 JSON and text separate observed logical sizes from unverified manifest hash accounting, report recorded run statuses and incomplete coverage, and exclude invalid declarations or conflicting hash sizes. Linked and reparse descendants are skipped. A missing default store is absent; explicit root errors exit 2, partial inspection 1 and complete inspection 0. Existing review formats and artifact copies remain unchanged.

- Session status accepts optional --session NAME_OR_ID and --request ID, shared with HTTP session/request query selectors. Exact requests require an explicitly selected managed session and return scoped retained facts, reply-only descendants, separate native/reply evidence and association limitations. Session activity cannot replace request disposition. Blank, repeated, malformed, unsupported and unknown selectors fail without falling back to a complete view. Provider-control attribution requires unique nonempty, context-consistent identities for both providers; unproved links remain unassigned. Omitted selectors retain the existing response structure. Reads start no controller/provider and perform no control, cursor or storage mutation.

- Managed project `.awkit` writers establish effective clone-local Git exclusion before payload, SQLite or provider startup, including direct sessions/channels, explicit review roots, check marks, hook persistence and pipeline state. Anchored rules cover nested projects, worktrees and submodules; concurrent awkit append/restore operations preserve existing bytes. Explicit writers reject failed protection and already tracked write targets without changing the index. Hooks report storage errors and skip persistence while preserving their host decision. Read-only paths, per-call `--no-git`, non-Git use, home installation and arbitrary external outputs retain their boundaries. Runtime-added rules remain unowned; retained runtime records keep their exclusion.

- Session creation supports Claude model IDs/aliases and optional effort low/medium/high/xhigh/max through the common CLI/HTTP/form. Requests are durable before construction and reapplied on owned exact-ID recovery; later canonical model observations remain separate and effective effort stays unverified. Codex exact-pair admission and override-free recovery remain. Status adds provider capability descriptions and per-session operation support without removing existing fields. Fresh forms select an available provider; saved choices/drafts are not switched when availability changes, and submit remains disabled for unavailable selections or pending initialization. Shared controls explain unavailable Claude discovery, foreign enrollment and active-turn steering; no transcript scan, new fallback or replay is added. Selection metadata remains an optional existing-store extension.

- Session create adds optional --reasoning-effort with an explicit Codex model, also available in the form. The request is retained separately and sent only as native model_reasoning_effort configuration at creation. Explicit effort mismatches hold work through the existing transactional admission guards across resume; model-only/default records keep native inheritance. Resume and turns receive no overrides. This does not establish model availability or per-turn execution configuration.

- Session create accepts an optional Codex-only model ID on the verified runtime. Explicit selections retain the request and native model/provider/effort observations separately; creation or resume mismatches hold work without fallback. Queue claims and native input admission check that hold transactionally, so late activity callbacks cannot release it. Resume and ordinary turns supply no model overrides. Legacy/default creation, Claude and enrollment behavior remain unchanged. The screen exposes the optional input and latest configuration without claiming model access, fixed effort or per-turn execution; validation errors remain visible inside the creation form with its draft. Selection metadata is an optional existing-store extension; no migration.

- The session screen shows retained native model observations with their creation/initialization source, leaving enrolled or history-only coverage unknown. It makes no per-turn execution claim and changes no model selection or policy. Exact-turn update errors distinguish an unavailable runtime/connection from a conversation with no observed active turn; ended work is still refused before native input.

- Session discover lists allowlisted current-project Codex metadata through an existing initialized owned connection on the verified runtime. Database-only forward pages retain scoped, expiring cursors; listing never starts, resumes or repairs a native conversation. The human enrollment dialog selects a native name and retains its exact ID and draft through refresh, paging and refusal. Enrollment/send remain separate, and manual exact-ID entry remains available. Discovery previews and raw errors are excluded before pending queues or event diagnostics; late discovery replies are suppressed without changing ordinary callbacks. No persistent schema changes. Exit 0 returns a page, 1 reports unavailable discovery, and 2 reports invalid input/control errors.

- Session status adds current_work, decision_summary and one public_update per correlated Codex attempt from retained completed public commentary. The general event window stays30. Agent/human reading separates local reservation/submission, native acknowledgement, linked replies and explicit handling; stale activity remains unknown. Respondable decisions are counted separately from submitted/native-unconfirmed callbacks and unavailable routes. No provider input, callback response, cursor movement or storage migration occurs on read; existing controls and exact-turn updates remain.

- Session update supplies an explicitly selected existing Codex assignment/expected native turn through turn/steer on the verified runtime. Agent and human routes persist intent/body/target/caller key before input; duplicate keys recover without replay, and ended/mismatched turns refuse without fallback. Status adds turn_updates and update_target. Existing core schema1/extensions3/4 store explicit local intent/dispatch/result event types without migration or new channel assignments. Original request/result links and send/notice/decision behavior remain. Native acknowledgement is separate from output adoption; restart retains uncertain updates. Exit0 acknowledges an update, exit1 retains refusal/uncertainty and exit2 reports input/control errors.

- Session decide accepts --input-file PATH, or - for UTF-8 stdin, containing the exact decision_id and choice. UTF-8 BOM is supported. Mixed argument/file input and malformed or ambiguous JSON are refused before dispatch. The selected session, existing decision handler, offered choices, permission semantics, JSON result schema and exit meanings remain unchanged; --decision with --choice or --answers-file still works.

### Guidance

- Development records now separate current task handoffs from versioned history. The evidence guide and repository-only catalogue group local validation collections by task references while preserving raw run paths, failures and incomplete attempts.

- Development records now open with current conclusions and next actions. The roadmap separates current work, deferred or blocked outcomes and completed units; earlier assignments and evidence remain available in the existing records.

- The session guide shows the existing CLI creation command before sending the first assignment, while retaining creation and follow-up through the human screen.

- The task handoff template requests actual drafts and any intermediate draft used, preserving the Korean guide's drafting-method choice.

### Examples

The producer leaves its own task record reachable from the project entry; the receiver verifies and revises the actual retained result. A fresh Codex-to-Claude use found no required public-direction repair. The task record separates informed assessment and retained operational failures from technical delivery, human acceptance and efficiency claims.

### Incompatible changes

- Explicit Codex enrollment creates managed extension 4; older controllers reject it. Existing extensions 1/2/3 retain their migration and creation behavior, and core channel schema remains 1. The new session enroll command and human entry select a name/native UUID without sending a task or injecting role/base instructions. Admission pins one verified Windows runtime and requires the same local home/store, project, native writer ownership, direct-input permission and interpretable required native policy. Every returned policy field is preserved and compared, including optional profile provenance; actual null and key absence remain distinct. Refusal and uncertain delivery remain visible without replacement or replay.

- Managed session extension 3 adds nullable observed native identity and separate Claude caller-UUID, echo and result-UUID fields. Versions 1/2 migrate under the controller lock; older controllers reject extension 3. Core channel schema 1 remains unchanged. Status adds claude_runtime capability details while retaining the boolean claude field.

- Managed session channels upgrade their extension from 1 to 2 transactionally under the owning controller lock. Delivery records add origin generation, client correlation and interruption intent; a cancellation projection retains pre-dispatch cancellation separately from later stop requests. Core channel schema 1, ordinary read-only channels and task messages/cursors remain unchanged. Older controllers reject extension 2. Session status JSON schema 1 adds posts, cancellations, dispositions, decision availability and returned_scope when resumed permissions differ; native decision IDs now also distinguish callbacks sharing an RPC ID. Reconnection preserves the saved effective permission policy and holds queued work if the returned sandbox or approval scope changes.

- `awkit usage --json` now defaults to result format 3. Thread and total `user_messages` may be `null` when human origin, identity, mixed representations or log coverage prevents an exact per-file count. New `user_message_coverage` records supported observations by representation, unclassified records and reasons separately from token/log `total.complete`. Modern Codex human markers are recognized; consistent message-ID replays count once, and distinct IDs are preserved. Mixed legacy/modern streams remain ambiguous without a correspondence key. Message-only logs retain threads with missing tokens. The table reports both coverage measures. Codex `counted` is now `model_context_rows`; `calls` and model-call totals keep their numerical meaning, including repeated context rows. Claude classification and token arithmetic are unchanged; no cross-file deduplication or task-cost accounting is added.

- Hook commands no longer append `|| exit 0`, which Windows PowerShell 5.1 rejects before awkit starts. Reinstalling hooks updates exact commands generated by earlier versions while preserving custom commands. The runner still handles rule errors; missing executables now remain visible as launch failures. After installation, restart the terminal and agent app to refresh PATH.

- The kit is installed in three layers. `awkit kit init` no longer appends a section to `AGENTS.md` or `CLAUDE.md`, writes no skills into the project and commits nothing: it writes `checks.toml` from the scan's draft with a new `[kit]` table (or adds the table, or its missing keys, to an existing file without changing the rest), calls `awkit kit hooks`, adds `.awkit/` to `.git/info/exclude`, records what it wrote in `.awkit/installed.json`, and prints the line a user may add to the instruction file. `--no-git` now means no hooks and no exclude line. It exits 2 only when `checks.toml` was complete and `.awkit/` already excluded. `awkit kit skills` writes into the user folders (`~/.claude/skills`, `~/.agents/skills`) for both agents by default, records them in `~/.awkit/installed.json`, takes `--without` and `--project`, and no longer requires `--provider`; `--kit` implies `--project`. The skills' generated line names the awkit version and says to update with `awkit kit skills`. `awkit kit remove` runs `awkit kit hooks --remove` first and takes `--user` (the user folders) and `--project` (the default). `kit scan` always reports `session_words` as measured, counting awkit's skills in the user folder as well. The release ZIP is the user skills bundle (`agent-work-kit-skills-VERSION.zip`, unpacked in the home folder) instead of the kit folder. `install.sh` and `install.ps1` run `awkit kit skills` before `awkit doctor`. The `[kit]` table is optional, so the check configuration keeps `schema = 1`.
- `awkit kit init` no longer copies the kit folder. It appends an Agent Work Kit section with the project profile to the end of `AGENTS.md` and `CLAUDE.md` (creating `AGENTS.md`, and a `CLAUDE.md` importing it, only when neither exists), writes self-contained skills, and records what it added in `.awkit/installed.json`, which replaces `VERSION.txt` for the version. `--copy` copies the folder as before, with `--name`. A kit is updated by running `awkit kit skills` again instead of installing a second folder beside it.
- `awkit kit skills` without `--kit` and without an `agent-work-kit` folder writes skills that hold the guides instead of pointing at a kit folder, and adds `awkit-workflow`. Descriptions are one line. Skills awkit wrote earlier are regenerated instead of kept. With a method bundle such as superpowers in the project, `awkit-work-types`, `awkit-delegation`, `awkit-review-session` and `awkit-records` are left out.
- `awkit kit hooks` no longer writes `rules.toml`; the handlers run `awkit hook --kit-rules`, which applies the kit's rules until the project has its own file. With an existing commit-msg hook it adds one line to it instead of leaving the check out, and with husky or pre-commit it uses their hook files. Settings files keep their indentation, line endings and characters (they were rewritten with two-space indentation and `\u` escapes). With a completion gate (kkamak, groundtruth, cngx) the done check is left out. It prints `connected:` for a line added to an existing hook, and `note:` lines.
- `install_skills` returns a dictionary (`created`, `updated`, `unchanged`, `kept`, `omitted`) and `install_hooks` one with `installed`, `connected`, `kept` and `notes`, for code that calls them.
- `awkit kit hooks --claude` writes `awkit hook` entries for every hook event to `.claude/settings.json`, which can be committed, and writes `rules.toml` when there is none; it no longer writes the done check to `.claude/settings.local.json` and removes the entries earlier versions put there. `--codex` writes the same to `.codex/hooks.json`.
- CLI help and error messages changed from Korean to English. Scripts that read message text should check exit codes instead; their meaning is unchanged.
- `awkit usage --json` uses result format 2: unmeasured token fields are `null` instead of `0`, and the result carries `format` and `total.complete`.
- `awkit review` resolves file names, step `cwd` and `artifacts` patterns relative to the folder it runs in. Run from the repository root it behaves as before; from a subfolder, the same subfolder of the worktree is the base, recorded as `subdir` in results and manifests.
- `awkit kit example` commits the folder it creates, creating the repository with `core.autocrlf=false` when there is none. Use `--no-git` to only copy.
- `awkit kit init --copy` no longer commits the folder or creates a repository: it writes the folder, prints what it wrote and, outside a repository, says so. `awkit kit init --commit` commits what init wrote in an existing repository (`checks.toml` and `rules.toml`, or with `--copy` the new folder); without it nothing is committed. `--no-git` with `--copy` changes nothing now. Scripts that relied on the commit should pass `--commit` or commit the files themselves.
- The kit is a baseline workflow plus situation guides. `templates/agent-instructions.md` is gone: `workflow.md` is the baseline read every session, and the connect procedure, check setup and delivery have their own guides (`connect.md`, `checking.md`, `delivery.md`). Instructions that pointed agents at the old file should point at `agent-work-kit/README.md`.
- The web extras moved to the `awkit.extras` package (`awkit.extras.pipeline`, `awkit.extras.publish`, `awkit.extras.ui`); the commands are unchanged.
- People-facing documentation is now the two READMEs only. The command documentation moved to `kit/reference.md` (English, shipped with the kit), and the development documents under `docs/` were merged into `docs/development.md`.

- `awkit kit hooks` writes `rules.toml` from the kit's default rules when the project has none, puts Claude Code's handlers in `.claude/settings.local.json` instead of `.claude/settings.json`, registers one handler per event (`awkit hook EVENT --kit-hooks || exit 0`), does the Git, Claude Code and Codex parts together unless one is chosen, and records what it writes in `.awkit/kit-hooks.json` instead of `.awkit/installed.json`. `kit hooks --remove` takes it out and asks before deleting a `rules.toml` changed since. `install_hooks` in `awkit.checks` keeps its earlier behavior for code that calls it.
- A `verify` hook rule on Stop blocks once per session instead of once per distinct output, and every block's reason ends with `(KIT/failures.md: ENTRIES)`.

It preserves non-ASCII and spaced paths without requiring awkit in the caller Python or a helper file inside the project. Snapshot behavior and Git configuration are unchanged.

### Fixed

- On Windows, replacing a JSON record, hook state, history view, session endpoint or published entry page retries for about three seconds while another process holds the target open. A check run previously stopped with WinError 5 when `result.json` was briefly held, leaving a `running` result and a retained worktree. A hold longer than the retry window still raises the original error; other platforms replace once, as before.

- A managed session attempt that became uncertain because the provider connection was lost stays uncertain when the provider's `turn/start` response is handled afterwards. The turn ID is still recorded for recovery. Previously that order reset the attempt to `accepted` and the session to `accepted` while no provider was connected; it also made a recovery test fail intermittently on Windows CI.

- Connection guidance selects HEAD only when it contains the intended check inputs; otherwise it uses explicitly selected current files in a snapshot. Check setup guidance points to per-worktree `[[setup]]` preparation and preserves snapshot-compatible dependency selection. Command behavior and separately hashed external configuration are unchanged.

- Bundled hook messages and newly generated rules now name the installed kit's readable guide folder. Resource lookup starts at the regular `awkit` package, avoiding a namespace object's `MultiplexedPath(...)` representation. Project-local kit precedence is preserved. Existing project rules are left untouched; previously generated malformed paths need separate repair.

- `awkit kit scan` makes its input absolute before resolving links. This avoids a Windows Python fallback that can repeat the current folder name when access to the trailing `.` is denied. Default, explicit-dot and absolute inputs select the same project; link resolution is retained.

- Review-session guidance now has both roles inspect new notices between work and recover unanswered requests on startup/resume. Bounded waits, read positions, completion and client wake-up limits are distinct. Independent-review prompts retain their roles; explicitly assigned other responsibilities do not become independent merely through channel addresses. No channel protocol or acknowledgement feature is added.

- Bundled hook rules now opt into `command_protocol = "awkit-v1"` and a restricted adapter with pass/finding/error results. Execution and protocol errors are logged and allowed without consuming a later violation's block opportunity; real findings retain their existing behavior. Unmarked custom/legacy rules are unchanged. Existing project copies require explicit per-rule migration after checking the actual interpreter's capability; an older runner/child means unavailable protection. The repository's exact default entries opt in; other settings and matching conditions are preserved. The commit helper's optional strict path exposes execution errors only to the adapter, keeping legacy behavior unchanged.

- Installers resolve the selected Python executable and pass it to pipx for fresh environments. POSIX discovery includes standalone `python3.14`; Windows prefers a usable PATH Python before the launcher. Existing app environments retain their interpreter, which `awkit doctor` reports. CI adds 3.14 tests alongside 3.11-3.13 and installer/installed-wheel checks on Windows and Linux at 3.12 and 3.14, with actual interpreter assertions and separate artifacts.

- `hook reply` now correlates recognized guide reads with their successful results and returned main-guide content. Successful CLI reads receive credit; failed reads and path mentions do not. Missing or ambiguous evidence remains fail-open and is distinct from confirmed access. Supported Claude/Codex shapes, the narrow current `exec` wrapper and the content heuristic are documented in the reference. The document trigger, one-block policy, generic command errors and hook settings are unchanged.

- Writing and done-check text summaries identify their scope: complete-file pattern checks, repository-state matching and configured-command success do not establish document review. Task checks and unmatched repository state are reported separately. The writing and reporting guides require omitted reviews to remain visible. Check logic, exit codes and JSON fields are unchanged.
- `doctor` now validates an existing `checks.toml` without executing its commands and warns about empty or invalid configuration. Its summary distinguishes available tools from warnings and unverified execution; exit codes and JSON finding fields remain unchanged. Repeated `kit init` retains the no-checks warning, and the connect guide establishes actual checks before running an empty draft.
- `doctor` reports the loaded package path and installation commit when matching metadata records one. Source execution reports its own checkout and local changes; unrelated installed metadata is not used. Unknown provenance remains explicit, without printing source URLs or credentials.

- Kit examples now show filled `[kit]` settings and distinguish automatic checks from review and delivery evidence. The role README gives explicit model mappings and generation commands for both Claude Code and Codex, alongside their existing generator defaults.

- `kit hooks` now excludes only the hook settings it created, with exact root-relative rules in `.git/info/exclude`; existing settings and tracked changes retain their Git treatment. Reinstallation repairs missing exclusions from recorded installs. `check done` follows Git for user settings, including `.claude/settings.local.json` and `CLAUDE.local.md`, so the documented snapshot recipe needs no filename filters. Hook removal removes its settings rules even when check records remain, preserves later edits, and restores unchanged exclude bytes and line endings. `.awkit/kit-hooks.json` adds `settings_excluded` entries; `.awkit/installed.json` records an `excluded` object with hashes and a backup instead of a boolean, and removal still reads older records. User additions to a generated Git hook survive removal.
- A rule message was measured after `{kit}` was filled in, so with awkit installed by pipx the kit's `korean-writing`, `research` and `delegation` rules exceeded 200 characters and were dropped as broken. The limit now applies to the text as written.
- A hook rule's `shell` condition matched the body of a heredoc fed to a program, so writing a file that mentions `git push` with `cat <<EOF` got the delivery line.
- The `commit-identity` hook rule judged a commit made after `cd` into another repository by the session's repository, and read the body of a heredoc fed to a program (a Python script holding a `git commit` string) as commands. It follows `cd` and skips such heredoc bodies.
- `awkit kit hooks --git` left the commit identity check out without saying so when the repository already had a commit-msg hook, and wrote into husky's generated `.husky/_` folder.
- `awkit kit scan` reported no kit in a project whose skills point at a kit folder other than `agent-work-kit`, such as this repository's `kit/`.
- `awkit doctor` passed a coding agent's Git identity such as `Claude <noreply@anthropic.com>` as fine. It now checks the configured identity against the repository's history, and `kit init` and `kit example` commit into a repository with history only as an identity that fits it, skipping the commit with the reason otherwise.
- The hooks from `awkit kit hooks` named the Python interpreter awkit was installed with and broke when that environment moved; they call `awkit` by name.
- `awkit check done` counted `.claude/settings.local.json`, which `kit hooks --claude` writes, as unchecked work and blocked every turn. Files local to the machine are left out, and the file is excluded from Git locally.
- `awkit review check` kept run folders in the system temp folder by default, outside the project; the default is now `.awkit/reviews` in the repository, excluded from Git locally.
- `awkit review snapshot` refused a file removed with `git rm` or moved away with `git mv`, since it looked for the file in the index; it now also accepts a file HEAD has.
- `awkit usage` did not count messages typed while a turn was running, which Claude Code records only as queued-command attachments.

- `awkit review` no longer creates a repository in an untracked folder and commits every file in it, `.env` included; such folders are refused.
- An example created inside a repository that already had commits was not committed, so the first command in its README could not find its script.
- Adding the kit to a repository with staged changes no longer bundles those changes into the kit's commit.
- `awkit usage` no longer counts notices, command output and interruption markers as user messages.
- `awkit kit scan` no longer suggests pytest for a bare `tests` folder and puts the checks CI already runs first.
- Two concurrent `awkit review accept` runs could mix accepted versions; a lock prevents it.
- Some tests failed when run from the repository root with `PYTHONPATH=src`.
