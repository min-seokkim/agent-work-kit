# Agent Work Kit

[English](README.md) | 한국어

Agent Work Kit은 Claude Code, Codex 같은 코딩 에이전트가 쓰는 작업 지침과 명령줄 도구 `awkit`입니다. 코드, 문서, 자료 조사, 데이터 작업에 쓸 수 있으며 프로그래밍 언어는 가리지 않습니다.

사용자는 원하는 결과를 설명하고 받아들일지 판단합니다. 에이전트는 키트에 따라 작업 범위를 정하고 요구사항을 보존하며, 고정한 버전을 검사합니다. 다른 세션이 이어받을 수 있도록 판단과 검증의 근거도 남깁니다.

## 왜 만들었나

에이전트에게 일을 맡긴 뒤에도 같은 요구사항을 다시 설명하거나, 수정 중에 사라진 문장을 되살리거나, 어느 버전을 검사했는지 확인해야 할 때가 있습니다. 여러 세션을 쓰면 사용자가 메시지를 중계하고 이전 결정을 찾아 전달하는 일까지 맡게 됩니다.

키트는 이런 작업에 공통 절차를 적용합니다. 구현 전에 목표를 정하고, 원자료와 승인한 결과를 보존하고, 확인한 내용과 남은 문제를 구분해 보고하도록 합니다. 이 중 일부는 훅과 검사 명령으로 확인합니다. 다음 작업에 필요한 결정은 프로젝트 기록에 남깁니다.

## 동작 방식

에이전트는 프로젝트에서 쓰던 지시문, 기록, 검사 명령을 먼저 확인합니다. 작업에 필요한 키트 지침을 읽고 다음 순서로 진행합니다.

1. 원하는 결과와 원자료, 수정 범위, 완료 기준을 정합니다. 담당자와 결과를 보관할 위치도 기록합니다.
2. 검사할 버전을 고정하고 별도 작업 사본에서 검사를 실행합니다. 명령, 로그, 지정한 결과 파일을 보관하며 실패한 시도도 남깁니다. 보관한 결과 파일이 이후에 바뀌었는지도 확인할 수 있습니다.
3. 수정본을 승인한 결과와 비교하고 내용을 검토한 뒤, 전달한 곳에서 결과를 확인합니다. 검사한 버전과 남은 문제, 다음 행동을 작업 기록에 남깁니다.

훅은 작업 중에 관련 지침을 출력하거나 설정된 조건을 검사합니다. 지정된 글쓰기 패턴을 찾고, 변경한 파일에 검사 통과 기록이 있는지 확인하는 식입니다.

여러 세션이 함께 일할 때는 로컬 채널에 요청, 검토 의견, 답변을 남깁니다. 세션 관리 기능으로 Codex나 Claude 대화를 시작하고, 브라우저의 로컬 화면에서 담당 작업과 답변, 결정을 기다리는 요청을 확인할 수 있습니다. 에이전트도 명령줄에서 같은 기능을 사용합니다. 설치된 에이전트를 이용하며, Claude에 필요한 추가 설치는 [세션 안내](kit/sessions.md)에 있습니다.

사용량 보고서는 Claude Code와 Codex 로그에서 모델과 토큰 사용량을 집계하고, 집계가 불완전한 경우 이를 표시합니다. 채널에는 서버가 필요하지 않으며 기본 패키지는 외부 Python 라이브러리에 의존하지 않습니다. 상세 절차는 에이전트용 [키트 안내](kit/README.md)에 있습니다.

## 작업 종류별 절차

| 작업 | 키트가 에이전트에게 안내하는 일 | 검토할 내용 |
|---|---|---|
| 코드 변경 | 고정한 버전에서 프로젝트의 검사를 실행합니다. | 검사한 버전, 테스트 로그, 확인하지 못한 동작 |
| 문서 작성 | 원문의 뜻과 승인된 선택을 보존하며 쓰거나 고칩니다. | 본문, 원자료와 대조한 내용, 수정 이유 |
| 데이터 분석 | 입력을 식별하고 분석 결과를 보관해 승인한 결과와 비교합니다. | 입력 해시, 계산, 바뀌거나 빠진 파일, 선택에 따라 추가된 파일 목록 |
| 자료 조사 | 출처의 주장, 관측값, 가정과 결론을 구분합니다. | 근거 자료, 판단 과정, 풀리지 않은 질문 |
| 설정 또는 전달 | 환경을 살펴보고 실제로 사용할 곳에서 결과를 확인합니다. | 진단 결과, 변경이 적용됐음을 확인할 근거 |

자동 검사는 프로젝트에서 정한 조건을 확인합니다. 내용을 읽고 쓸모를 판단해 결과를 받아들이는 일도 검토에 포함됩니다. 다른 세션이 같은 버전을 검토하고 채널로 의견을 돌려줄 수도 있습니다.

### 문서 작성

작성 지침은 독자, 목적, 원자료를 확인하는 일부터 시작합니다. 사실과 조건, 저자의 뜻을 보존하고, 작은 수정은 영향을 받는 대목에 한정하도록 합니다. 사용자가 수정을 요구한 이유도 이후 관련 작업에 적용하도록 안내합니다.

초안 작성 방법은 문서의 목적과 사용자 요구에 맞춰 정합니다. 한국어 글은 사실, 자연스러운 문장, 전체 구성을 따로 검토하고 화면에 표시된 결과도 확인합니다. 내장 검사는 지정된 글쓰기 패턴을 찾고 버전별 지적을 비교합니다. 원문의 뜻을 지켰는지, 논증이 타당한지는 글을 읽으며 판단합니다. 상세 절차는 [작성 지침](kit/writing.md)과 [한국어 작성 지침](kit/korean-writing.md)에 있습니다.

## 시작하기

awkit에는 Python 3.11 이상과 Git이 필요합니다. 현재 설치 스크립트는 `dev` 브랜치를 사용합니다.

Windows에서는 PowerShell에 입력하세요.

```powershell
irm https://raw.githubusercontent.com/min-seokkim/agent-work-kit/dev/install.ps1 | iex
```

macOS나 Linux에서는 터미널에 입력하세요.

```sh
curl -fsSL https://raw.githubusercontent.com/min-seokkim/agent-work-kit/dev/install.sh | sh
```

설치 스크립트는 필요한 도구가 없으면 Windows에서는 winget, macOS에서는 Homebrew로 설치합니다. Linux에서는 빠진 패키지를 알려 줍니다. 이어서 [pipx](https://pipx.pypa.io)로 awkit을 설치하고, 지침을 사용자 스킬로 저장한 뒤 설치 상태를 점검합니다. `awkit` 명령을 찾지 못하면 새 터미널을 여세요.

프로젝트 폴더에서 다음 명령을 실행하세요.

```sh
awkit kit init
```

이어서 에이전트에게 이렇게 요청하세요.

> 이 프로젝트에 Agent Work Kit을 연결해 주세요.

이 명령은 프로젝트 설정을 추가하고 기존 훅과 함께 awkit 훅을 연결합니다. 기존 지시문, 스킬, 메모리 파일은 보존하며 커밋은 하지 않습니다. 에이전트는 프로젝트 요구사항을 채우고 검사 명령을 확인합니다. 사용법을 익히려면 내장 데이터 예제를 실행해 달라고 해도 됩니다. 잘못된 열 이름으로 검사가 실패하고, 수정 후 실행한 검사에는 별도의 근거가 남습니다.

업데이트할 때는 설치 스크립트를 다시 실행하고, 에이전트에게 프로젝트 연결을 점검하고 지침을 다시 읽도록 요청하세요. 설치 스크립트는 awkit과 사용자 스킬을 갱신하며 프로젝트 설정, 훅, 프로젝트 안의 지침은 기존 내용을 유지합니다. 다른 설치 방법과 진단, 제거 절차는 [명령어 참고 문서](kit/reference.md)에 있습니다.

## 상태

개발 중이며 아직 릴리스한 버전은 없습니다. 첫 릴리스 전까지 명령과 파일 위치가 바뀔 수 있습니다. 이 저장소의 작업에도 키트를 사용하며, 확인한 결과와 한계를 [개발 근거 자료](docs/evidence.md)에 기록합니다. 사용량이나 검사 통과만으로 작업 시간이 줄었거나 결과가 좋아졌다고 판단하지는 않습니다.

남은 개발 항목은 [로드맵](docs/roadmap.md), 변경 사항은 [CHANGELOG.md](CHANGELOG.md)에 있습니다. 개발에 참여하려면 [개발 안내](docs/development.md)부터 읽으세요.

MIT 라이선스로 배포합니다. 작성 지침에는 `im-not-ai`를 바탕으로 고친 내용이 포함돼 있으며, 출처와 라이선스는 [외부 자료 고지](kit/THIRD_PARTY_NOTICES.md)에 있습니다.
