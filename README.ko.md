# Agent Work Kit

[English](README.md) | 한국어

Agent Work Kit은 Claude Code, Codex 같은 코딩 에이전트가 쓰는 작업 지침과 명령줄 도구입니다. 이 키트를 쓰는 에이전트는 작업을 끝냈다고 보고할 때 어떤 파일을 검사했는지, 그 파일에 프로젝트의 어떤 검사를 돌렸는지, 검사 결과가 무엇이었는지를 함께 남깁니다. 코드, 문서, 데이터, 자료 조사에 쓸 수 있고 프로그래밍 언어는 가리지 않습니다.

Git 프로젝트에서 에이전트에게 일을 거듭 맡기고, 돌아온 결과를 다시 확인하느라 이미 시간을 쓰는 사람을 위한 도구입니다. 개발자가 아닌 사람이 문서 하나를 한 번 만드는 일에는 아직 그만큼 편하게 쓰기 어렵습니다.

## 왜 만들었나

에이전트는 확인할 근거 없이 작업을 끝냈다고 보고하는 일이 많습니다. 흔한 경우는 다음과 같습니다.

- 테스트를 통과했다고 하지만, 다른 버전의 파일로 돌렸거나 아예 돌리지 않았습니다.
- 한 곳을 고치면서 이미 승인한 문서나 결과를 바꿉니다.
- 검토하는 동안 작성자가 계속 고쳐서, 실제로 나간 버전은 아무도 검토하지 않았습니다.
- 세션을 새로 열 때마다 프로젝트를 다시 설명해야 합니다.
- 한국어 문서가 번역한 글처럼 읽힙니다.

## 동작 방식

`awkit kit init`으로 키트를 넣은 뒤 에이전트에게 키트를 연결하라고 하면 됩니다. 에이전트는 프로젝트를 살펴보고, 무엇을 완료로 볼지와 결과를 누가 받는지 묻습니다. 에이전트는 그 답을 `checks.toml`에 적고, 프로젝트에 이미 있는 명령으로 검사를 설정합니다.

그 뒤로 작업은 모두 같은 순서로 진행합니다.

1. 에이전트가 목표, 고쳐도 되는 파일, 완료를 판단할 검사를 적습니다.
2. 바꾼 파일을 스냅샷으로 저장합니다. 스냅샷은 Git commit이며, 작업 중인 브랜치와 폴더는 바뀌지 않습니다.
3. 프로젝트의 별도 사본에서 스냅샷에 검사를 돌리고, 로그와 결과 파일을 해시와 함께 남깁니다.
4. 사람이 결과를 승인하면 그 결과를 채택본으로 보관하고, 이후 버전은 채택본과 비교합니다.
5. 다른 검토가 필요하면 다른 에이전트 세션이 같은 스냅샷을 검토하고, 주고받는 메시지에 그 스냅샷을 적습니다.

구현 세션과 검토 세션을 따로 열어 같은 컴퓨터의 채널로 요청과 결과를 주고받을 수 있습니다. 서로 다른 공급자의 에이전트도 연결할 수 있습니다. 채널에는 별도 서버가 필요 없고, 기본 패키지는 추가 Python 라이브러리 없이 실행됩니다. 연결 방법은 [검토 세션 지침](kit/review-session.md)에 있습니다.

## 작업 종류별 절차

| 작업 | 에이전트가 하는 일 | 끝난 뒤 확인할 수 있는 것 | 도구가 검사하는 것과 에이전트에게 맡기는 것 |
|---|---|---|---|
| 코드 변경 | 작업을 기록하고, 변경을 스냅샷으로 저장하고, 별도 사본에서 검사를 돌립니다. | 스냅샷 ID, 검사 로그, 확인하지 못한 범위 | 도구가 검사합니다. 프로젝트의 검사를 스냅샷에 돌리고 로그와 결과 파일을 보관합니다. |
| 한국어 문서 | 지켜야 할 사실을 적고, 영어로 초안을 쓴 뒤 한국어로 다시 쓰고, 사실, 문장, 구성을 따로 검토합니다. | 문서, 그리고 대조에 쓴 사실 목록 | 대부분 에이전트에게 맡깁니다. `awkit check writing`이 가운뎃점이나 섞인 어미 같은 기계적인 패턴은 찾지만, 글이 자연스러운지는 에이전트가 판단합니다. |
| 데이터 정리와 분석 | 입력 파일의 해시를 남기고, 관측값과 가정과 해석을 나눠 적습니다. | 입력까지 거슬러 확인할 수 있는 결과 파일, 데이터와 대조한 가정 | 파일로 된 데이터는 도구가 검사하고 결과 파일을 해시와 함께 보관합니다. 관측값과 해석을 나누는 일은 에이전트에게 맡깁니다. |
| 자료 조사, 환경 설정 등 | 작업 유형별 지침에 따라 먼저 고정할 것, 지킬 것, 물어볼 때를 정합니다. | 결과, 출처나 근거, 빠진 부분 | 출처가 질문에 맞는지는 에이전트가 판단합니다. |
| 독립 검토 | 다른 세션이 고정한 스냅샷을 검토합니다. | 그 스냅샷에 연결된 검토 의견 | 스냅샷은 도구가 고정하고, 검토 내용은 검토하는 세션이 판단합니다. |

## 시작하기

awkit을 쓰려면 Python 3.11 이상과 Git이 필요하고, 아직 릴리스한 버전은 없습니다. 설치 스크립트는 Git이나 Python이 없으면 먼저 설치합니다. Windows는 winget, macOS는 Homebrew를 쓰고, Linux에서는 설치할 패키지를 알려 줍니다. 그다음 [pipx](https://pipx.pypa.io)로 개발 브랜치의 awkit을 설치하고, 키트의 가이드를 사용자 폴더에 스킬로 넣은 뒤 `awkit doctor`를 실행합니다. 빠진 것이 남아 있으면 이 명령이 고치는 방법을 알려 줍니다. 가이드는 일하는 사람의 방식이라서 프로젝트마다 넣지 않고 컴퓨터에 한 번만 둡니다.

처음 설치할 때는 현재 터미널에서 찾은 Python을 사용합니다. 기존 pipx 환경을 업데이트할 때는 사용하던 Python을 유지합니다. `awkit doctor`로 awkit을 실행하는 Python을 확인하세요.

Windows에서는 PowerShell에 입력하세요.

```powershell
irm https://raw.githubusercontent.com/min-seokkim/agent-work-kit/dev/install.ps1 | iex
```

macOS나 Linux에서는 터미널에 입력하세요.

```sh
curl -fsSL https://raw.githubusercontent.com/min-seokkim/agent-work-kit/dev/install.sh | sh
```

Python, Git, pipx가 이미 설치돼 있다면 `pipx install "git+https://github.com/min-seokkim/agent-work-kit@dev"`로 설치한 뒤 `awkit kit skills`와 `awkit doctor`를 실행하세요. 첫 릴리스에는 Python 없이 문서 작업이나 조사만 하는 사람을 위해 홈 폴더에 풀기만 하면 되는 스킬 ZIP도 함께 올립니다.

프로젝트 폴더에서 다음 명령을 실행하세요.

```sh
awkit kit init
```

이 명령은 프로젝트에서 이미 돌리는 검사로 `checks.toml`을 만들고, 이 프로젝트에서 무엇을 완료로 볼지 적는 `[kit]` 표를 넣습니다. 기존 훅을 보존하면서 awkit 훅을 추가하고, awkit이 쓰는 `.awkit/` 폴더는 Git에서 뺍니다. 커밋은 하지 않습니다. 원래 있던 지시문과 스킬, 메모리 파일도 건드리지 않습니다. `AGENTS.md`나 `CLAUDE.md`에 붙일 한 줄은 화면에 보여 주기만 하니, 원하면 직접 붙이세요. 커밋할 파일은 `checks.toml`과 `rules.toml`뿐입니다.

그리고 에이전트에게 이렇게 말하세요.

> 이 프로젝트에 Agent Work Kit을 연결해 주세요.

업데이트할 때는 위의 설치 스크립트를 다시 실행하세요. `dev` 브랜치에서 awkit을 다시 설치하고, 사용자 폴더에서 awkit이 관리하는 스킬을 갱신합니다. 각 프로젝트의 설정과 훅, 복사한 가이드, 프로젝트 안의 스킬은 그대로 둡니다. 프로젝트마다 `awkit doctor`로 연결 상태를 확인하세요. 실행 중인 에이전트는 갱신된 가이드를 다시 읽어야 할 수 있습니다.

`awkit kit remove`는 프로젝트에서, `awkit kit remove --user`는 사용자 폴더에서 키트를 뺍니다. 스킬을 쓰지 못하는 에이전트는 `awkit kit guide workflow`로 가이드를 읽습니다.

예제로 먼저 써 보려면 에이전트에게 `awkit kit example data demo`를 실행하고 그 README대로 진행하라고 하세요. 예제는 열 이름 하나가 틀린 작은 데이터 프로젝트입니다. 에이전트가 검사를 돌려 실패를 확인하고, 입력을 고친 뒤 다시 검사하고, 보관한 파일을 보여 줍니다.

개발 중이며, 첫 릴리스 전까지 명령과 파일 위치가 바뀔 수 있습니다. 이 저장소의 작업에도 awkit을 직접 사용하고, 잘 작동한 점과 실패한 점을 [개발 기록](docs/evidence.md)에 남깁니다. 바뀐 내용은 [CHANGELOG.md](CHANGELOG.md)에 있습니다.
