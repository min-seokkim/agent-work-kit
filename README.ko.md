# Agent Work Kit

[English](README.md) | 한국어

Agent Work Kit은 Claude Code, Codex 같은 코딩 에이전트가 쓰는 작업 지침과 명령줄 도구입니다. 에이전트가 작업 요구사항을 보존하고, 결과의 특정 버전을 검사하고, 확인한 근거와 함께 보고하도록 돕습니다. 코드, 문서, 데이터, 자료 조사에 쓸 수 있고 프로그래밍 언어는 가리지 않습니다.

Git 프로젝트에서 에이전트에게 일을 거듭 맡기고, 결과를 다시 확인하거나 같은 요구사항을 설명하느라 시간을 쓰는 사람을 위한 도구입니다. 사용자는 원하는 일을 설명하고 결과를 검토합니다. 상세 지침을 읽고 도구를 실행하는 일은 에이전트가 맡습니다.

## 왜 만들었나

에이전트와 하는 일은 목표를 정하고 자료를 조사하는 단계부터 결과를 만들고 수정하고 전달하는 단계까지 이어집니다. Agent Work Kit은 이 과정에서 반복되는 문제를 다룹니다.

- 해결할 문제와 완료 기준이 분명해지기 전에 구현부터 시작합니다.
- 자료 조사나 분석에서 출처의 사실, 관측값, 가정과 해석을 섞어 결론을 냅니다.
- 수정하면서 저자의 뜻을 바꾸거나 이미 승인한 내용, 입력 자료, 결과를 빠뜨립니다.
- 테스트와 검토를 거친 버전이 실제 전달한 버전과 다릅니다.
- 여러 세션이 같은 일을 중복해서 하거나 요청을 답변 없이 남깁니다. 사용자는 메시지를 중계하고 이전 결정을 다시 설명해야 합니다.
- 설정이나 전달 명령은 성공했지만, 실제로 적용됐는지 또는 받는 사람이 결과를 받았는지는 확인하지 않습니다.
- 여러 모델과 세션으로 작업이 나뉘면 사용량을 파악하기 어렵습니다.

## 동작 방식

키트를 연결하면 에이전트가 프로젝트에서 쓰던 지시문과 기록, 검사 방법을 살펴봅니다. 무엇을 완료로 볼지와 결과를 누가 받을지도 확인합니다. 내장 진단 기능은 빠진 도구와 연결 문제, 맞지 않는 설정을 찾아 에이전트가 기존 환경에 맞춰 작업 절차를 설정할 수 있게 합니다.

이후에는 작업을 시작하고 수정하고 전달하는 과정에 다음 기능을 사용합니다.

1. 에이전트가 작업 전에 목표와 원자료, 수정 범위, 완료 기준을 정합니다. 조사와 분석 지침에 따라 출처의 주장, 관측값, 가정과 결론을 구분합니다.
2. 에이전트는 해당 작업에 필요한 지침을 읽습니다. 훅은 작업 중에 관련 지침을 출력하거나 검사를 실행합니다. 지정된 글쓰기 패턴을 찾고, 변경한 파일에 검사 통과 기록이 있는지 확인합니다.
3. 스냅샷으로 검사할 버전을 고정합니다. 작업 중인 브랜치를 바꾸지 않고 별도 사본에서 검사를 돌려 로그와 지정한 결과 파일을 보관합니다. 보관한 파일이 이후에 바뀌지 않았는지도 확인할 수 있습니다.
4. 승인한 결과 파일을 채택본으로 남깁니다. 다음 수정본과 비교하면 바뀌거나 빠진 파일, 새로 보관한 파일을 확인해 이전 작업이 의도치 않게 달라진 부분을 검토할 수 있습니다.
5. 별도 세션끼리 로컬 채널에서 요청과 검토 의견, 답변을 주고받습니다. 서로 다른 공급자의 에이전트도 연결할 수 있습니다. 미응답 요청과 기록된 담당 업무를 조회하고, 다음 세션이 이어 갈 맥락은 프로젝트의 인계 기록에 남깁니다.
6. 전달 지침에 따라 실제 사용할 곳에서 결과를 확인합니다. 실행 중인 프로그램에 설정이 적용됐는지, 게시한 버전이 목적지에 있는지, 받는 사람이 파일을 받았는지 확인하도록 합니다.

사용량 보고서는 Claude Code와 Codex의 세션 로그에서 모델과 토큰 사용량을 집계하고, 정보가 불완전한 항목을 표시합니다. 자원을 얼마나 썼는지 살펴볼 수 있지만, 이 수치로 결과의 품질이나 절약한 시간을 판단하지는 않습니다.

로컬 채널에는 별도 서버가 필요 없고, 기본 패키지는 추가 Python 라이브러리 없이 실행됩니다. 상세 설정과 명령 사용법은 에이전트가 읽는 [키트 지침](kit/README.md)에 있습니다.

## 작업 종류별 절차

| 작업 | 에이전트가 하는 일 | 끝난 뒤 확인할 수 있는 것 |
|---|---|---|
| 코드 변경 | 작업을 기록하고, 변경을 스냅샷으로 저장하고, 프로젝트의 기존 검사를 돌립니다. | 검사한 버전, 로그, 보관한 결과 파일, 검사하지 못한 범위 |
| 문서 작성 | 원자료의 사실과 저자의 의도를 보존하고, 사실과 문장, 구성을 검토합니다. | 문서, 원자료와 대조한 내용, 수정한 이유 |
| 데이터 정리와 분석 | 입력 파일의 해시를 남기고, 관측값과 해석을 구분하고, 보관한 결과를 채택본과 비교합니다. | 사용한 입력, 달라진 결과, 선택에 따라 새로 보관한 파일 목록 |
| 자료 조사와 환경 설정 | 출처와 가정, 환경을 확인한 결과, 전달을 확인할 근거를 기록합니다. | 결과, 뒷받침하는 근거, 풀리지 않은 질문 |
| 독립 검토 | 다른 세션이 고정한 스냅샷을 검토하고 채널로 의견을 보냅니다. | 해당 버전에 대한 검토 의견, 답변, 남은 요청 |

자동 검사는 프로젝트에서 정한 조건을 확인합니다. 결과가 질문에 답하는지, 실제로 쓸 수 있는지는 별도로 검토해야 합니다.

### 문서 작성

문서 작성 지침은 독자와 목적을 정하는 일부터 원자료 보존, 초안 작성, 수정까지 다룹니다. 에이전트는 초안을 쓰기 전에 원문을 확인하고, 지켜야 할 사실과 조건, 저자의 의도를 정리합니다. 계획을 완료한 일로 쓰거나, 저자가 던진 질문을 요약 과정에서 다른 뜻으로 바꾸지 않도록 합니다.

한국어 문서는 영어 초안을 쓴 뒤 그 뜻을 자연스러운 한국어로 다시 쓰도록 안내합니다. 사실, 한국어 문장, 문서 전체의 구성을 차례로 검토하고 화면에 표시된 결과도 확인합니다. 작은 수정은 영향을 받는 대목에 범위를 맞추고, 이미 승인한 문서를 고칠 때는 채택된 표현과 구성을 보존합니다.

사용자가 수정 의견을 주면 에이전트는 그 이유와 적용 범위를 파악해 이후 관련 초안과 인계에도 반영하도록 합니다. 다음 세션에서도 찾을 수 있도록 요구사항은 프로젝트에서 쓰던 기록에 남깁니다.

내장 글쓰기 검사는 한국어 어미 혼용처럼 지정된 패턴을 찾습니다. 버전별 검사 결과를 비교해 어느 지적이 남았는지도 살펴볼 수 있습니다. 원문의 뜻을 지켰는지, 논증이 타당한지, 문장이 자연스러운지는 글을 읽으며 판단합니다. 에이전트가 따를 상세 절차는 [작성 지침](kit/writing.md)과 [한국어 작성 지침](kit/korean-writing.md)에 있습니다.

## 시작하기

awkit에는 Python 3.11 이상과 Git이 필요합니다. 아직 릴리스한 버전은 없으며, 설치 스크립트는 `dev` 브랜치를 사용합니다.

Windows에서는 PowerShell에 입력하세요.

```powershell
irm https://raw.githubusercontent.com/min-seokkim/agent-work-kit/dev/install.ps1 | iex
```

macOS나 Linux에서는 터미널에 입력하세요.

```sh
curl -fsSL https://raw.githubusercontent.com/min-seokkim/agent-work-kit/dev/install.sh | sh
```

설치 스크립트는 Git이나 Python이 없으면 Windows에서는 winget, macOS에서는 Homebrew로 설치합니다. Linux에서는 필요한 패키지를 알려 줍니다. 그다음 [pipx](https://pipx.pypa.io)로 awkit을 설치하고, 가이드를 사용자 스킬로 저장한 뒤 설치 상태를 점검합니다.

프로젝트 폴더에서 다음 명령을 실행하세요.

```sh
awkit kit init
```

그리고 에이전트에게 이렇게 말하세요.

> 이 프로젝트에 Agent Work Kit을 연결해 주세요.

프로젝트 설정을 만들고 기존 훅과 함께 awkit 훅을 연결합니다. 기존 지시문과 스킬, 메모리 파일은 그대로 두며, 커밋은 하지 않습니다. 이어서 에이전트가 프로젝트의 요구사항을 채우고 제안된 검사 명령을 확인합니다. 내장된 데이터 예제로 사용법을 익혀 달라고 해도 됩니다. 잘못된 열 이름을 찾아 고치는 예제로, 실패한 검사와 수정 후 통과한 결과가 남습니다.

업데이트할 때는 설치 스크립트를 다시 실행하고, 에이전트에게 프로젝트 연결을 점검하고 갱신된 지침을 다시 읽도록 요청하세요. 설치 스크립트는 awkit과 사용자 스킬을 갱신하며, 프로젝트별 설정과 훅, 프로젝트 안의 가이드는 그대로 둡니다. 다른 설치 방법이나 진단, 제거 절차는 에이전트가 [명령어 참고 문서](kit/reference.md)에서 확인할 수 있습니다.

## 상태

개발 중이며, 아직 릴리스한 버전은 없습니다. 첫 릴리스 전까지 명령과 파일 위치가 바뀔 수 있습니다. 이 저장소의 작업에도 awkit을 사용하며, 실제 작업에서 확인한 결과를 [개발 기록](docs/evidence.md)에 남깁니다.

앞으로 할 일은 [로드맵](docs/roadmap.md), 변경 사항은 [CHANGELOG.md](CHANGELOG.md)에 있습니다. 개발에 참여하려면 [개발 안내](docs/development.md)부터 읽으세요.

MIT 라이선스로 배포합니다. 작성 지침의 일부는 `im-not-ai`의 자료를 고쳐 썼으며, 출처와 라이선스는 [외부 자료 고지](kit/THIRD_PARTY_NOTICES.md)에 있습니다.
