# Development history

Read [the current development entry](../development.md) first. Records here preserve earlier assignments, decisions, verification and limitations. Their source revision appears at the top; a historical status or owner does not describe a live task.

| History | Use it for |
|---|---|
| [Task records](../tasks/README.md) | Open a current task, then its named historical section or full record. Each `history/tasks/<id>.md` corresponds to `tasks/<id>.md`. |
| [Roadmap](roadmap.md) | Earlier item numbers, candidate guards, prerequisites and proposal follow-up |
| [Document workflow plan](document-workflow-plan.md) | Original phases, contracts and trial observations |
| [Evidence](evidence.md) | Milestones, measurement tables and verification qualifications |
| [Development entry](development.md) | The previous capability summary and navigation |

Retain the historical wording and source identifiers. Relative links are adjusted when records move; local `.awkit/` paths still start at the repository root. Add new conclusions to the current task and link the supporting receipt. If a retained contract changes, record the decision in the current task or design document and identify what it supersedes.
