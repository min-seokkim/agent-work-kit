# 구현 계획

Agent Work Kit은 에이전트가 실제 작업을 수행하도록 돕는 지침과 실행 도구를 함께 제공합니다. 개발, 문서 작성, 자료 조사, 데이터 정리와 환경 설정에서 같은 절차를 씁니다. 이 문서는 현재 구현과 다음 작업을 구분합니다. 현재 동작은 [CLI 사용법](cli.md)과 [추가 도구](tools.md)에, 검사한 범위는 [검증 범위](validation.md)에 있습니다.

2026-10-22 기준이며 기준 커밋은 `5081d5d` 이후의 구현 브랜치입니다. 패키지 버전은 아직 `0.2.0`이고, 다음 릴리스에서 올립니다.

## 현재 구현

| 기능 | 동작 |
|---|---|
| 첫 실행 예제 | `awkit kit example documents` 또는 `data`가 결함 하나를 넣은 작은 프로젝트를 만듭니다. README가 검사 실패 확인, 수정, 스냅샷 재검사, 보존한 결과 확인을 안내합니다. 예제는 wheel에 들어 있습니다. |
| 공통 키트 | 작업 지침, 상태 규약, 적용표의 "Start here" 다섯 항목, 작업 유형별 완료 근거, 작업·검토·결정·재개 양식을 제공합니다. |
| 한국어 문서 작성 | 사실과 조건을 보존하고 영어 초안을 거쳐 한국어로 쓰며 사실, 문장, 전체 흐름을 검토합니다. |
| 역할 파일 | 다섯 역할의 지침과 모델 설정을 공급자별 파일로 만듭니다. |
| 검토 스냅샷 | HEAD에 지정한 파일의 변경을 얹은 Git commit 객체를 만듭니다. |
| 격리 검사 | 고정한 버전의 worktree에서 단계별 실행 폴더로 준비 명령과 검사 명령을 실행하고 결과와 로그를 보존합니다. |
| 결과물 보존과 대조 | 검사 설정의 `artifacts`에 맞는 파일을 실행 기록 폴더에 복사하고 크기와 SHA-256을 manifest에 남깁니다. `required_artifacts`가 없으면 실패로 기록합니다. `awkit review verify`가 보존한 파일을 다시 대조하고 중단된 실행을 표시합니다. |
| 검토 채널 | 공유 SQLite 파일에 요청, 응답과 반박을 저장하고 대기와 종료를 처리합니다. 읽음 위치는 역할별로 공유합니다. |
| 사용량 집계 | 실행 기록에서 모델과 토큰을 스레드별로 모읍니다. 측정하지 못한 필드는 `null`로 표시하고 합계에 완전 여부를 붙입니다(결과 형식 2). |
| 배포 결과 확인 | 프로젝트 명령을 실행하고 실제 버전과 필수 검사를 확인합니다. 불확실한 상태와 복귀 결과를 구분합니다. |
| 로컬 문서 발행 | 허용 파일과 링크를 검사하고 진입점을 교체합니다. 해시로 확인한 이전 버전을 복원합니다. |
| 화면 검토 시트 | 여러 화면 폭의 캡처와 가로 넘침 검사 결과를 모읍니다. |
| 개발 환경 | CLI 도움말과 진단 메시지는 영어입니다. Ruff가 오류, import 순서와 최신 문법을 검사하고 CI에서 실행됩니다. |

## 이번 구현에서 조정한 것

계획했던 명령 가운데 일부는 기존 기능을 넓히는 쪽으로 바꿨습니다.

| 계획 | 실제 구현 | 이유 |
|---|---|---|
| `awkit example init <종류> <폴더>` | `awkit kit example <종류> <폴더>` | 키트 복사와 같은 패키지 자료 복사 기능이라 `kit` 아래에 두었습니다. 새 최상위 명령을 늘리지 않습니다. |
| 새 `artifact.py`와 `awkit artifact capture` | 검사 설정의 `artifacts`, `required_artifacts` | 보존할 결과물은 거의 항상 검사 실행의 산출물입니다. 실행기가 검사 직후 복사하면 어떤 commit과 설정에서 나온 파일인지 저절로 연결되고, 프로젝트마다 복사 스크립트를 쓰지 않아도 됩니다. Git 저장소 밖의 폴더를 독립적으로 보존하는 명령은 실제 필요가 확인될 때 추가합니다. |
| `awkit artifact verify`와 `awkit inspect <실행 기록 폴더>` | `awkit review verify <실행 기록 폴더>` | 두 명령이 읽는 자료가 같습니다. 하나의 명령이 manifest 대조, 추가 파일 보고, 중단된 실행 표시를 모두 맡습니다. |
| `kit/work-types.md`와 `kit/examples/general-work.md` | `kit/work-types.md` 하나 | 작업 유형별 입력, 보존 항목, 완료 근거와 멈출 시점을 한 문서에 두고 작업 지침, 작업 양식, 적용표에서 연결했습니다. |
| 최소 적용표 별도 파일 | 적용표 맨 위의 "Start here" 절 | 파일을 하나 더 두면 두 적용표가 어긋납니다. 같은 문서 안에서 다섯 항목을 먼저 채우게 했습니다. |

## 다음 작업

| 순서 | 작업 | 완료를 판단할 근거 |
|---|---|---|
| 1 | 릴리스 준비 | 버전을 올리고 결과 형식 2와 영어 메시지 전환을 릴리스 노트에 적습니다. Windows에서 전체 테스트와 wheel 설치 후 예제 실행을 확인합니다. |
| 2 | 예제의 첫 사용 시간 측정 | 새 환경에서 설치부터 `verify`까지 실제로 걸린 시간과 막힌 지점을 기록합니다. 10분을 넘기는 단계가 있으면 README나 명령을 고칩니다. |
| 3 | 사용량 집계의 실제 기록 대조 | Claude Code와 Codex의 현재 기록 파일로 형식 2의 값을 각 도구가 보여 주는 사용량과 맞춰 봅니다. 어긋나는 필드는 `missing`이나 `invalid`로 드러나야 합니다. |
| 4 | 검토 채널의 수신 확인 | 실제 검토 세션에서 같은 역할로 읽는 세션이 둘 이상 생기거나, 읽었다는 사실과 지적을 처리했다는 사실을 구분해야 하는 경우가 확인되면 소비자별 읽음 위치와 명시적 수신 확인을 추가합니다. 기존 DB를 트랜잭션으로 전환하고 실패 시 원래 메시지로 복구하는지 검사합니다. |
| 5 | 다른 환경으로 전달 | 요청 ID, 기준 버전, 보존한 결과물과 응답을 담는 내보내기·가져오기 형식을 정하고 로컬에서 반복 입력과 버전 불일치를 검사합니다. 원격 연결은 실제로 연결할 두 환경이 정해진 뒤 설계합니다. |

4와 5는 실제 사용에서 필요가 확인된 뒤 시작합니다. 현재 채널은 역할마다 세션 하나를 전제하며, 그 안에서는 `wait … request`가 답하지 않은 요청을 정확히 보여 줍니다.

## 기능을 받아들이는 기준

새 기능은 실행 예제에서 어떤 실패를 막고 어떤 반복 작업을 줄이는지 보여야 합니다. 기존 명령과 결과 형식을 넓혀서 해결할 수 있으면 그쪽을 먼저 택하고, 결과 형식이 바뀌면 버전과 전환 안내를 함께 둡니다. 구현에는 실행 예제, 실패 진단, 복구 방법과 중요한 실패 경로의 테스트가 따릅니다.

## 검증과 효과 측정

공개 예제와 테스트에는 모의 자료를 사용합니다. 실제 세션에서 발견한 문제는 일반 요구사항으로 옮기며 개인 원문, 이름, 경로와 파일을 배포 자료에 넣지 않습니다.

변경한 기능의 중요한 실패 경로를 먼저 검사하고 배포 묶음마다 Windows와 Linux의 전체 테스트와 wheel 설치 검사를 수행합니다. 첫 실행 단계 수, 수동 확인, 수정 횟수, 같은 근거를 다시 찾은 작업과 완료 후 발견된 중요 결함을 기록합니다.

시간과 사용량에는 확인 범위를 표시합니다. 요청한 모델과 실제 기록된 모델을 구분하고, 토큰, 비용 추정치와 실제 차감액도 따로 다룹니다. 위임 효과는 [위임 지침](../kit/delegation.md)의 측정 기준을 따릅니다.
