# 개발 계획

Agent Work Kit은 에이전트의 개발 작업, 한국어 문서 작성과 결과 검증을 돕습니다. 제품의 책임 범위와 기능을 추가하는 기준은 [역할과 범위](scope.md)에 정리했습니다. 이 문서는 현재 구현과 다음 작업을 구분합니다.

## 현재 구현

0.2.0에서 사용할 수 있는 기능입니다. 사용법은 [CLI 사용법](cli.md)과 [추가 도구](tools.md)에, 검사한 범위는 [검증 범위](validation.md)에 있습니다.

| 기능 | 현재 동작 |
|---|---|
| 공통 키트 | 작업 지침, 상태 규약, 프로젝트 적용표와 작업·검토·결정·재개 양식을 제공합니다. |
| 한국어 문서 작성 | 사실과 조건을 보존하고 영어 초안을 거쳐 자연스러운 한국어로 쓰는 절차와 검토 기준을 제공합니다. |
| 역할 파일 | 다섯 역할의 지침과 모델 설정을 공급자별 파일로 만듭니다. |
| 검토 스냅샷 | HEAD에 지정한 파일의 변경을 얹은 Git commit 객체를 만듭니다. |
| 격리 검사 | 고정한 버전의 worktree에서 준비와 검사 명령을 실행하고 결과와 로그를 남깁니다. |
| 검토 채널 | 같은 PC의 SQLite 파일에 요청, 응답과 반박을 저장하고 대기와 종료를 처리합니다. 읽음 위치는 역할별로 공유합니다. |
| 사용량 집계 | 자체 파서로 실행 기록의 모델과 토큰을 스레드별로 모읍니다. |
| 배포 결과 확인 | 프로젝트 명령을 실행하고 대상, 실제 버전과 필수 검사를 확인합니다. 불확실한 상태와 복귀 결과를 기록합니다. |
| 로컬 문서 발행 | 허용 파일과 링크를 검사하고 진입점을 교체합니다. 해시로 확인한 이전 버전을 복원할 수 있습니다. |
| 화면 검토 시트 | 여러 화면 폭의 캡처와 가로 넘침 검사 결과를 모읍니다. |

## 우선 작업

아래 항목은 후속 구현입니다. 연결 완료나 검증 완료를 뜻하지 않습니다.

| 순서 | 작업 | 완료를 판단할 근거 |
|---|---|---|
| 1 | 사용량 수집 연결 | 같은 표본에서 중복 기록, 누적값, 모델, 기간과 메인·자식 구분을 대조합니다. 집계 출처와 버전을 남기고 기존 명령의 전환 방법을 확인합니다. |
| 2 | 검토 전달의 신뢰성 | 조회, 읽음과 명시적 수신 확인을 나눕니다. 수신자별 상태를 관리하고, 승인 철회와 미처리 지적이 있을 때 종료 조건을 검사합니다. 다른 세션이 먼저 읽는 경우를 재현해 확인합니다. |
| 3 | 재개와 재검토 절차 | 완료한 단계와 그 근거를 재사용하고, 수정한 범위를 중심으로 다시 검토합니다. 반복 판정이 길어지면 메인이 원인과 작업 분할을 다시 판단하도록 규칙과 양식을 맞춥니다. |

채널에서는 메시지를 받았다는 확인과 지적을 해결했다는 판정을 별도로 기록해야 합니다. 기존 DB에서 기록을 보존하며 전환하는 방법도 검사합니다.

## 다음 적용에서 확인할 것

| 항목 | 확인할 내용 |
|---|---|
| 실제 모델 | 요청한 모델과 실행 기록의 모델을 대조하고, 필요한 판정 조건을 충족했는지 기록합니다. |
| 작업별 근거 | 작업 ID에 스냅샷, 검사 설정, 결과, 검토 기록과 관련 세션을 연결합니다. |
| 사용량의 의미 | 토큰, 로그 비용 추정치, 요율 환산치와 실제 차감액을 구분합니다. 알 수 없는 값은 미확인으로 남깁니다. |
| 문서 재작업 | 대표 결과 확인, 작은 묶음 작성, 완료한 초안과 검토 재사용이 반복 작업을 줄이는지 봅니다. |
| 첫 적용 사례 | 작은 실제 변경을 구현, 검사, 수정과 재검토까지 수행하고 남은 기록으로 과정을 설명할 수 있는지 확인합니다. |
| 실행 환경 연결 | 필요한 프로젝트에서 검사 환경, 브라우저 검사와 배포 명령을 연결하고 결과가 같은 버전에 대응하는지 봅니다. |

프로젝트가 사용하는 명령과 결과를 연결하고, 실제 적용에서 필요한 항목부터 하나씩 검증합니다.

## 효과를 확인하는 방법

비슷한 작업에서 걸린 시간, 총사용량, 보정 횟수와 완료 후 발견된 중요 결함을 함께 기록합니다. 메인과 자식의 사용량을 구분하고, 문서 재작성이나 같은 근거의 반복 확인에 든 비용도 살핍니다. 위임 방식의 비교 기준은 [위임 지침](../kit/delegation.md)의 측정 절을 따릅니다.

## 기능을 마쳤다고 볼 조건

- 운영 인증값 없이 모의 자료로 성공 경로와 중요한 실패 경로를 확인할 수 있습니다.
- 실제 연결을 주장하는 기능은 해당 환경에서 결과를 대조했습니다.
- 대상 버전, 설정, 실행 결과와 남은 제한이 기록됩니다.
- 설치, 사용, 실패 진단과 재개 방법을 문서에서 찾을 수 있습니다.
- 기존 기록과 명령에 영향이 있다면 전환 방법을 제공합니다.
