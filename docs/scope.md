# Agent Work Kit의 역할과 범위

2026-10-22 확정한 제품 범위입니다. 기능을 추가하거나 연결 방식을 바꿀 때 이 문서를 기준으로 판단합니다. 구현 순서는 [개발 계획](roadmap.md)에, 현재 동작은 [CLI 사용법](cli.md)과 [추가 도구](tools.md)에 정리합니다.

## 목적

Agent Work Kit은 에이전트와 개발하기 위한 작업 지침, 한국어 문서 작성 가이드, 검증 도구를 제공합니다. 작업의 목표와 완료 조건을 정하고, 사람이 읽고 이해할 수 있는 문서를 쓰며, 변경한 버전에 검사와 검토 근거를 남기도록 돕습니다.

Markdown 키트에는 작업, 위임, 한국어 문서 작성, 검토, 결정과 재개 기록의 기준을 담습니다. 선택해서 쓰는 CLI는 변경본 고정, 검사 실행, 검토 메시지 전달과 결과 기록을 돕습니다. 프로젝트의 언어와 실행 환경은 적용표와 명령 설정으로 연결합니다.

## Agent Work Kit이 맡는 기능

| 기능 | 제공할 결과 |
|---|---|
| 작업 기준과 기록 | 목표, 수정 범위, 완료 조건, 현재 상태와 다음 행동을 같은 기준으로 기록합니다. |
| 한국어 문서 작성 | 사실과 조건을 보존하면서 자연스러운 한국어로 쓰고, 사실과 문장, 전체 흐름을 검토하는 지침을 제공합니다. |
| 검토 스냅샷 | 지정한 변경을 고정하고 검사자와 검토자가 같은 버전을 확인하게 합니다. |
| 검사 근거 | 고정한 버전에 프로젝트의 검사 명령을 실행하고 설정, 종료 상태와 로그를 남깁니다. |
| 검토 전달 | 요청과 응답, 지적의 처리 결과를 연결하고 누가 무엇을 확인했는지 구분합니다. |
| 완료 판단 | 산출물별 검사와 전달 조건, 확인한 단계, 남은 지적과 검토 재사용 조건을 기록합니다. |
| 작업별 사용량 해석 | 수집한 모델과 사용량을 작업에 연결하고 재작업이나 추가 판정의 이유를 함께 남깁니다. |
| 배포 결과 확인 | 요청한 버전과 실제 버전, 검사 결과, 실패와 복구 결과를 구분합니다. |
| 로컬 정적 문서 발행 | 허용한 빌드 파일을 검사하고 해시로 버전을 관리하며 진입점 교체와 복원을 수행합니다. |

이 표는 제품의 책임 범위입니다. 작업 기록은 현재 Markdown 양식으로 작성하며, 모든 근거를 자동으로 연결하는 기능은 후속 작업입니다. 메시지 수신 확인과 작업별 사용량 연결도 [개발 계획](roadmap.md)에서 구현 상태를 구분합니다.

## 실행 환경과의 연결

프로젝트가 이미 사용하는 명령과 결과 형식을 연결합니다. 다음 기능의 실행과 관리는 해당 프로젝트의 환경이 맡고, Agent Work Kit은 작업에 필요한 식별자와 근거를 기록합니다.

| 프로젝트 환경이 맡는 일 | Agent Work Kit이 연결할 정보 |
|---|---|
| 에이전트 실행, 모델 설정과 작업 배정 | 담당 작업, 요청한 모델, 실행 기록과 결과 |
| 사양 관리와 작업 의존성 관리 | 기준 문서, 작업 ID와 상태를 관리하는 위치 |
| 빌드, 검사, 테스트 DB와 서비스 구성 | 대상 버전, 실행 명령, 설정과 검사 결과 |
| 공급자별 로그 해석과 사용량 집계 | 세션 식별자, 실제 모델, 사용량과 집계 출처 |
| 브라우저 동작 검사와 이미지 비교 | 검사 대상, 보고서, 캡처와 실행 추적 자료 |
| 서버 배포, 원격 잠금, 이미지 전달과 데이터 복원 | 배포 대상, 버전, 실제 상태와 복구 결과 |
| 문서 렌더링, 호스팅과 발행 대기열 | 빌드 결과물, 발행 버전과 실행 결과 |

기능마다 필요한 연결만 선택합니다. 같은 작업 상태를 관리하는 기준 위치는 한 곳으로 정하고 다른 기록에서는 그 위치를 참조합니다. 연결 도구와 버전, 명령, 결과 위치는 프로젝트 적용표에 기록합니다.

에이전트 실행기, 범용 작업 스케줄러, 공급자별 집계 엔진, 인프라 관리와 호스팅 플랫폼은 자체 개발 범위에서 제외합니다. Agent Work Kit의 연결 기능은 기존 명령 호출과 결과 해석에 필요한 크기로 유지합니다.

## 현재 기능을 다루는 원칙

CLI는 `awkit`이라는 이름으로 실행하며, 0.2.0의 하위 명령 구조를 유지합니다. 자체 로그 집계기는 결과 대조와 전환 방법을 확인한 뒤 사용량 수집 연결로 정리합니다. 화면 캡처는 검토 자료를 만드는 기능으로 유지하고, 동작 검사와 이미지 비교 결과를 연결하는 방향으로 발전시킵니다.

배포 실행기는 프로젝트 명령을 호출하고 실제 결과를 확인하는 범위를 유지합니다. 로컬 문서 발행은 신뢰하는 정적 빌드 결과물의 검사, 교체와 복원에 집중합니다. 연결 방식을 바꾸더라도 기존 기록과 오류 상태의 의미를 보존합니다.

## 새 기능을 받아들이는 기준

1. 실제 작업에서 필요한 결과와 완료 조건을 설명할 수 있어야 합니다.
2. 위 책임 범위 중 어느 기능을 보완하는지 명확해야 합니다.
3. 기존 명령과 결과를 연결하는 방법을 먼저 검토하고, 남는 필요만 구현합니다.
4. 대상 버전, 실행 결과와 실패 원인을 확인할 수 있어야 합니다.
5. 설정, 진단, 재개 방법과 중요한 실패 경로의 검증을 함께 제공합니다.

효과는 작업을 마치는 데 걸린 시간, 재작업, 사용량과 완료 뒤 발견된 중요 결함으로 확인합니다. 역할 수나 기능 수는 성과 기준으로 삼지 않습니다.
