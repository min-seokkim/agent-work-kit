## Selected behavior

`kit hooks` inserts project-local `env.AWKIT_CLAUDE_BASH_PATHS="git-bash"` only when the key is absent; existing values remain unowned. For native Windows and raw `Bash` events, the outer hook activates conversion only when the delivered environment and current local declaration both equal `git-bash`. It reads only the already-resolved rule root's local settings. Missing or mismatching declarations make that commit rule unavailable before conversion or identity lookup; nested roots receive no guessed fallback. This is configuration freshness, not proof of provider origin. Insertion into tracked or staged local settings is refused, with a selector-specific note; unknown tracking status also skips insertion, while known non-Git folders remain supported. Existing hook installation, shared command generation, duplicate-handler avoidance and legacy command migration continue.

The outer hook carries the mode internally and adds one private argument only to the exact opted-in bundled commit adapter. Each drive-rooted `cd` or `git -C` component is normalized before joining. Relative paths, native absolute drive paths and UNC meanings are preserved. Unsupported roots and ambiguous paths report unavailable protection without a fallback repository or shell execution. Invalid selection and selected check failures add visible context while preserving existing allow/block policy and other rules.

The schema-1 installation record gains optional per-file `owned_env` metadata. Removal retains exact unchanged-file restoration; edited files lose only a matching owned key in addition to existing marked-handler removal. Missing records and changed values preserve the selector. Older removers restore unchanged files but cannot remove the selector from edited files.

The coupled backup correction reserves fresh exclusive hook-file and exclusion backups before changing the files they protect, recording actual paths in the existing receipt fields. Removal deletes only recorded, hash-matching backups inside the managed backup folder and empty directories. Unknown or changed copies survive; the `.awkit/` exclusion remains when they keep that directory in use. Older readers can still restore recorded paths, while older removal code retains its broader directory cleanup.
