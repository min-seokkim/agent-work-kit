## Reporting an actual run

Use the existing task record to keep three outcomes separate:

1. Mechanical integrity: input and revision identities, relative links, writing-pattern checks and any snapshot checks actually run. Report first failures and omitted checks.
2. Agent judgments: passages inspected, preserved distinctions, candidate deviations, disagreements, corrections and rendered inspection by the named reviewer and method. Fixture declarations and a second agent's agreement establish neither independent factual verification nor human approval.
3. Human use: actual edits, unintended changes, repeated work, acceptance and effort when observed. Without human participation, correction burden and acceptance remain unmeasured.

Retain the assigned prompt and language method, guide revision, fresh-context boundaries, first output, intermediate draft when required, corrections and evaluator prior exposure. Record actual model and effort from execution metadata when available; a request or self-report alone does not establish them. For a paired comparison, use neutral candidate labels and disclose model or context differences and reviewer exposure.

Packaging and hashes certify no semantic answer. A single pair or recurrence cannot establish a language-method winner, causal guide effect, model advantage, financial savings or delegation benefit. An unperformed review or rendered inspection stays unperformed even when mechanical checks pass.
