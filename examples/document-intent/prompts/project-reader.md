# Project-wide retrieval in a fresh context

Use a fresh context with the supplied coverage project root and these entry points: `finished/display.md` and `finished/absence.md`. All ordinary records under that root are available from the outset. Discover relevant records yourself. Do not read evaluator material, prior reader answers or another participant's output.

Follow the current [workflow](../../../kit/workflow.md), [writing guide](../../../kit/writing.md) and [protocol](../../../kit/protocol.md). Establish the project's questions from available material, then report how far each has developed. Cite substantive passages supporting every claimed stage and list the files actually inspected. A filename alone establishes no development stage.

Distinguish absence from inspected finished documents from evidence about the whole project. Separate source availability, proposals, collected research, drafting, fixture-declared review, author approval and publication. Keep inaccessible coverage unknown and state disagreements or unsupported claims.

Retain the first answer and any later corrections separately. Report review or rendering that was not performed. Describe the scope of this small fixture when reporting retrieval results; do not infer reliability in larger projects or actual author acceptance.
