# 프로젝트별 적용 예시

아래 예시는 적용표를 채울 때 확인할 자료를 설명합니다. 실행 가능한 기본 설정이나 해당 언어의 빌드 검증 결과는 아닙니다. 실제 명령은 각 저장소에서 확인하세요.

| 프로젝트 | 언어별로 확인할 자료 | 적용표에 적을 내용 |
|---|---|---|
| JavaScript 애플리케이션 | `package.json`, 잠금 파일, 기존 CI | 실제 런타임과 패키지 도구, 준비 명령, 저장소에서 정의한 검사 스크립트 |
| Go 서비스 | `go.mod`, 빌드 설정, 기존 CI | 사용하는 Go 환경, 검사할 패키지 범위, 외부 서비스가 필요한 검사와 격리 방법 |
| Java 애플리케이션 | 빌드 설정, 제공된 wrapper, 기존 CI | Java 환경, 사용할 빌드 도구, 모듈별 검사 명령과 실행 폴더 |
| 문서 중심 프로젝트 | 문서 빌드 안내, 링크 검사 설정, 발행 규칙 | 렌더링과 링크 검사 명령, 확인할 화면, 공개할 파일 범위 |

공통 작업 기록은 언어가 달라도 유지합니다. 작업 ID, 목표, 담당 파일과 기준 버전을 정하고 실제 검사 근거를 남긴 뒤 검토합니다. 다른 세션에 넘길 때는 같은 재개 양식을 사용합니다.

## 명령을 기록하는 예

프로젝트에서 확인한 실행 파일과 인자를 명령별로 적습니다. 셸 해석이 필요하다면 셸을 명시하세요. 아래 값은 작성 위치를 보여주는 빈 양식입니다.

| 명령 이름 | 실행 폴더 | 실행 파일과 인자 | 준비 조건 | 기대 결과 | 부수 효과 |
|---|---|---|---|---|---|
| 빠른 검사 | | | | | |
| 통합 검사 | | | | | |
| 문서 확인 | | | | | |

이 표를 자동으로 읽어 실행하는 기능은 아직 없습니다. 사람이나 에이전트가 해당 프로젝트에서 확인한 명령을 실행하고 결과를 기록합니다.

## 배포 실행기를 연결하는 경우

프로젝트의 언어와 관계없이 기존 배포 프로그램을 인자 배열로 연결할 수 있습니다. 대상과 버전을 읽는 명령, 백업, 배포, 검증, 복귀 명령이 필요합니다. 실제 상태를 읽어 정해진 JSON 결과를 반환하는 부분은 해당 프로젝트에서 구현해야 합니다.

공통 작업 기록만 사용하는 경우에는 이 연결이 필요하지 않습니다. Python이 필요한 범위는 선택한 CLI를 실행하는 PC이며, 애플리케이션의 구현 언어를 바꾸지는 않습니다.
